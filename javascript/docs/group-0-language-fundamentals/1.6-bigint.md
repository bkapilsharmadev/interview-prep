# BigInt in JavaScript

> "When regular numbers aren't big enough — BigInt to the rescue."

---

## 1. Concept Overview

**BigInt** (ES2020) provides arbitrary-precision integers, solving JavaScript's integer size limitations. Unlike `number`, which can only safely represent integers up to `Number.MAX_SAFE_INTEGER` (2^53 - 1), BigInt can represent integers of any size.

Key characteristics:
- Created by appending `n` to literals or using `BigInt()` constructor
- Cannot mix with `number` in operations (must convert explicitly)
- Supports all standard arithmetic operations
- Useful for cryptography, large IDs, precise calculations

## 2. Creating BigInt Values

### 2.1 Literal Syntax

```javascript
let big = 9007199254740991n;  // Append 'n'
let bigger = 999999999999999999999n;

// Hexadecimal, binary, octal
let hex = 0xFFn;
let binary = 0b1010n;
let octal = 0o777n;
```

### 2.2 Constructor

```javascript
BigInt(9007199254740991);     // 9007199254740991n
BigInt("999999999999999999"); // 999999999999999999n
BigInt(0x1f);                 // 31n

// From number (must be safe integer)
BigInt(Number.MAX_SAFE_INTEGER);  // 9007199254740991n
BigInt(Number.MAX_SAFE_INTEGER + 1);  // RangeError if unsafe
```

## 3. BigInt Operations

### 3.1 Arithmetic

```javascript
let a = 10n;
let b = 20n;

a + b;    // 30n
a - b;    // -10n
a * b;    // 200n
a / b;    // 0n (division truncates, returns BigInt)
a % b;    // 10n
a ** 2n;  // 100n

// Cannot mix with number
// 10n + 5;  // TypeError: Cannot mix BigInt and number
```

### 3.2 Comparison

```javascript
10n > 5;        // true (can compare with number)
10n === 10;     // false (different types)
10n == 10;      // true (loose equality allows comparison)
Object.is(10n, 10);  // false

// Sorting
[3n, 1n, 2n].sort((a, b) => a < b ? -1 : a > b ? 1 : 0);
```

## 4. Type Conversion

### 4.1 BigInt to Number

```javascript
let big = 9007199254740991n;

Number(big);           // 9007199254740991
+big;                  // TypeError (unary + doesn't work)
parseInt(big);         // 9007199254740991

// Precision loss warning
let huge = 999999999999999999999n;
Number(huge);         // 1e+21 (precision may be lost)
```

### 4.2 Number to BigInt

```javascript
BigInt(42);            // 42n
BigInt(3.14);          // RangeError (must be integer)
BigInt("42");          // 42n
BigInt(Number.MAX_SAFE_INTEGER);  // 9007199254740991n
```

### 4.3 String Conversion

```javascript
let big = 123n;

String(big);           // "123"
big.toString();        // "123"
big.toString(16);      // "7b" (hexadecimal)
big.toString(2);       // "1111011" (binary)
```

## 6. Limitations & Gotchas

### 6.1 No Decimal Support

```javascript
// BigInt only represents integers
// 3.14n;  // SyntaxError

// Division truncates
10n / 3n;  // 3n (not 3.333...)
```

### 6.2 JSON Serialization

```javascript
let obj = { id: 123n };

JSON.stringify(obj);  // TypeError: Do not know how to serialize a BigInt

// Workaround: convert to string
let obj2 = { id: "123" };
// Or use a replacer
JSON.stringify(obj, (key, value) =>
  typeof value === 'bigint' ? value.toString() : value
);
```

### 6.3 Math Operations

```javascript
// Math methods don't work with BigInt
Math.max(1n, 2n);     // TypeError
Math.abs(-5n);        // TypeError

// Use BigInt operations instead
1n > 2n ? 1n : 2n;   // 2n
-5n < 0n ? -(-5n) : 5n;  // 5n
```

## 7. Real-World Use Cases

### 7.1 Large IDs

```javascript
// Twitter-style snowflake IDs
let tweetId = 12345678901234567890n;

// Database IDs beyond safe integer range
let userId = BigInt("999999999999999999999");
```

### 7.2 Cryptography

```javascript
// Large prime numbers for RSA
let prime = 982451653n;

// Modular arithmetic
function modPow(base, exp, mod) {
  return base ** exp % mod;
}

let result = modPow(2n, 1000n, 97n);
```

### 7.3 Precise Calculations

```javascript
// Financial calculations (avoid floating-point)
let cents = 1999n;  // $19.99 in cents
let tax = cents * 8n / 100n;  // 8% tax
let total = cents + tax;  // 2159n ($21.59)
```

## 9. Common Pitfalls & Best Practices

### Pitfall 1: Mixing with Numbers

```javascript
// ❌ Problematic
function add(a, b) {
  return a + b;  // TypeError if one is BigInt and other is number
}

// ✅ Better
function add(a, b) {
  if (typeof a === 'bigint' || typeof b === 'bigint') {
    return BigInt(a) + BigInt(b);
  }
  return a + b;
}
```

### Pitfall 2: JSON Serialization

```javascript
// ❌ Problematic
let data = { id: 123n };
JSON.stringify(data);  // TypeError

// ✅ Better
let data = { id: 123n };
JSON.stringify(data, (key, value) =>
  typeof value === 'bigint' ? value.toString() : value
);
```

### Pitfall 3: Division Truncation

```javascript
// ❌ Problematic (if expecting decimal)
let result = 10n / 3n;  // 3n (not 3.333...)

// ✅ Better: Use number for decimals, BigInt for integers
let result = 10 / 3;  // 3.333...
```

### Best Practice: Use When Needed

```javascript
// Use BigInt only when:
// 1. Exceeding MAX_SAFE_INTEGER
// 2. Need arbitrary precision
// 3. Working with cryptography
// 4. Handling very large IDs

// Otherwise, use number for better performance and compatibility
```
