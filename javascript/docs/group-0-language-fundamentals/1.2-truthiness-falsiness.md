# Truthiness & Falsiness in JavaScript

> "Not all values are created equal — especially when JavaScript decides what is true or false."

---

## 0. What is Type Coercion? (Read This First)

Before talking about truthiness, you must understand what coercion means.

### Definition (Interview-Ready)

**Type coercion** is JavaScript's automatic or explicit process of converting a value from one type to another (string → number → boolean → object, etc.) based on the context where the value is used.

JavaScript has **3 forms of coercion**:

| Type | Triggered By | Example |
|------|-------------|---------|
| **ToString** | concatenation, template literals | `5 + "px"` → `"5px"` |
| **ToNumber** | arithmetic, `==` | `"5" - 1` → `4` |
| **ToBoolean** | conditionals, logical operators | `if (value) {}` |

**Truthiness/falsiness is simply:**

> The result of coercing a value using `ToBoolean(value)` from the ECMAScript spec.

In other words:

> "If JavaScript converted this value into a boolean automatically, would it result in `true` or `false`?"

---

## 1. Concept Overview

JavaScript evaluates values as truthy or falsy in boolean contexts, such as:

- Conditional statements (`if`, `while`, `for`)
- Logical operators (`&&`, `||`, `!`)
- Ternary operator (`condition ? a : b`)
- Default-value patterns (`value || fallback`)

These constructs depend on truthiness evaluation, not strict boolean comparison.

## 2. The 8 Falsy Values

JavaScript has exactly **8 falsy values** — the only ones for which `ToBoolean(value)` → `false`:

1. `false` — the boolean false
2. `0` — the number zero
3. `-0` — negative zero
4. `0n` — BigInt zero
5. `""` — empty string
6. `null` — null value
7. `undefined` — undefined value
8. `NaN` — Not a Number

**Everything else is truthy**, including:
- Any non-empty string: `"0"`, `"false"`, `" "` (whitespace)
- Arrays: `[]` (empty arrays)
- Objects: `{}` (empty objects)
- Functions: `function(){}`

### Why Are Arrays/Objects Truthy?

**Because all objects coerce to `true`** — JavaScript does not inspect their contents.

Objects internally are references, and **reference types always evaluate to truthy**. This is why an empty array `[]` or empty object `{}` is truthy, even though they contain no data. JavaScript checks if the value is an object reference, not whether it's "empty."

## 3. Truthiness in Practice

### 3.1 Conditional Statements

```javascript
let value = "";

if (value) {
  console.log("Truthy");
} else {
  console.log("Falsy");  // Executes
}

// Common patterns
if (user.name) {  // Checks if name exists and is non-empty
  console.log(user.name);
}

if (items.length) {  // Checks if array has elements
  console.log("Has items");
}
```

### 3.2 Logical Operators and Coercion

```javascript
// && → returns first falsy or last truthy
0 && "hello";       // 0 (short-circuits on falsy)
"hello" && "world"; // "world" (returns last truthy)
null && "hello";    // null (short-circuits on falsy)

// || → returns first truthy or last falsy
0 || "hello";      // "hello" (returns first truthy)
"hello" || "world" // "hello" (short-circuits on first truthy)
null || undefined; // undefined (returns last falsy)

// ! → negates truthiness (coerces to boolean first)
!0        // true (0 is falsy, so !0 is true)
!!"hello" // true (double negation: converts to boolean)
```

## 4. Common Truthiness Patterns

### 4.1 Checking for Value Existence

**❌ Problem** — `0` and `""` become falsy:

```javascript
if (count) { /* ... */ }  // 0 is treated as missing!
if (name) { /* ... */ }   // "" is treated as missing!
```

**✅ Explicit checks:**

```javascript
if (count !== undefined && count !== null) { /* ... */ }
if (name != null && name !== "") { /* ... */ }
```

**✅ Best** — nullish coalescing:

```javascript
const displayCount = count ?? 0;        // Only null/undefined → default
const displayName = name ?? "Anonymous"; // Only null/undefined → default
```

### 4.2 Array/Collection Checks

**❌ Wrong:**

```javascript
if (items) {  // Always true if items is an array (even if empty!)
  console.log("Has items");
}
```

**✅ Correct:**

```javascript
if (items && items.length > 0) {
  console.log("Has items");
}

// Or use optional chaining
if (items?.length) {
  console.log("Has items");
}
```

### 4.3 Object Property Checks

```javascript
let user = { name: "John", age: 0 };
```

**❌ Wrong** — loses zero:

```javascript
if (user.age) {  // 0 is falsy, so this won't run!
  console.log(user.age);
}
```

**✅ Correct:**

```javascript
if (user.age !== undefined) {
  console.log(user.age);
}

// Or use 'in' operator
if ('age' in user) {
  console.log(user.age);
}
```

- "What's the difference between `if (obj.prop)` and `if ('prop' in obj)`?"
- "When should you use truthiness checks vs explicit comparisons?"

## 5. Edge Cases & Gotchas

### 5.1 Empty Arrays and Objects

```javascript
if ([]) {
  console.log("Empty array is truthy!");
}

if ({}) {
  console.log("Empty object is truthy!");
}

// To check if actually empty
if (arr.length === 0) { /* empty array */ }
if (Object.keys(obj).length === 0) { /* empty object */ }
```

### 5.2 Strings "false" and "0"

**Both are truthy** — they are non-empty strings:

```javascript
if ("false") console.log(true);  // true (non-empty string)
if ("0") console.log(true);     // true (non-empty string)
```

**To interpret correctly:**

```javascript
str === "false"           // Check for string "false"
Number(numStr) === 0       // Check for numeric zero
```

### 5.3 Negative Zero

```javascript
let negZero = -0;
if (negZero) {  // false (negative zero is falsy)
  console.log("This won't print");
}

// Distinguishing -0 from +0
Object.is(-0, 0);  // false
Object.is(0, -0);  // false
```

### 5.4 Boolean Wrapper Objects

```javascript
// ⚠️ Important: Boolean wrapper objects are truthy!
new Boolean(false);  // truthy object!
if (new Boolean(false)) {
  console.log("This runs!");  // Because it's an object, not a primitive
}

// Always use primitive booleans
let isValid = false;  // ✅ Correct
let isValid = new Boolean(false);  // ❌ Wrong (creates truthy object)
```

### Interview Prompts

- "Why is `"false"` truthy but `false` is falsy?"
- "How do you distinguish between `-0` and `+0`?"
- "What's the truthiness of `new Boolean(false)`? Why?"

## 6. Boolean Conversion Techniques

### 6.1 Explicit Conversion

```javascript
// Boolean() constructor
Boolean(0);     // false
Boolean("");    // false
Boolean([]);    // true
Boolean({});    // true

// Double negation (common pattern)
!!value  // Converts to boolean
!!0      // false
!!"hello" // true
!![]     // true
```

### 6.2 Implicit (Logical Contexts)

These do `ToBoolean(value)` automatically:

```javascript
if (value) { /* ... */ }
while (condition) { /* ... */ }
value && doSomething();
value || defaultValue;
```

## 7. Real-World Patterns

### 7.1 Default Values

**`||` treats falsy as "missing":**

```javascript
let n = user.name || "Anonymous";  // "" → "Anonymous" ❌ (loses empty string)
```

**`??` treats only null/undefined as missing:**

```javascript
let n = user.name ?? "Anonymous";  // "" preserved ✔ (only null/undefined → default)
```

### 7.2 Short-Circuit Evaluation

```javascript
// && for conditional execution
user && user.logout && user.logout();

// || for fallbacks
const apiUrl = process.env.API_URL || "http://localhost:3000";

// Chaining
const value = obj?.prop?.nested || defaultValue;
```

### 7.3 Guard Clauses

```javascript
function processUser(user) {
  if (!user) return;  // Early return if falsy
  if (!user.name) return;  // Early return if name is falsy
  
  // Process user...
}
```

## 9. Common Pitfalls & Best Practices

### Pitfall 1: Assuming Empty Collections Are Falsy

```javascript
// ❌ Wrong
if (items) {  // Always true if items is an array
  processItems(items);
}

// ✅ Correct
if (items && items.length > 0) {
  processItems(items);
}
```

### Pitfall 2: Losing Zero Values

```javascript
// ❌ Wrong
let count = user.postCount || 0;  // If postCount is 0, becomes 0 (okay)
let score = game.score || 0;  // If score is 0, becomes 0 (okay)

// But this is problematic:
function displayCount(count) {
  if (count) {  // 0 is falsy!
    console.log(count);
  }
}

// ✅ Correct
function displayCount(count) {
  if (count !== undefined && count !== null) {
    console.log(count);
  }
}
```

### Pitfall 3: String "false" Confusion

```javascript
// ❌ Problematic
let setting = localStorage.getItem("featureEnabled");
if (setting) {  // "false" string is truthy!
  enableFeature();
}

// ✅ Correct
let setting = localStorage.getItem("featureEnabled");
if (setting === "true") {
  enableFeature();
}
```

### Best Practice: Be Explicit

```javascript
// When checking existence, be explicit
if (value !== null && value !== undefined) { /* ... */ }
// Or use nullish coalescing
const result = value ?? defaultValue;

// When checking for specific values, use strict equality
if (count === 0) { /* ... */ }
if (name === "") { /* ... */ }
```
