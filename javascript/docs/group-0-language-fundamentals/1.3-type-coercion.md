# Type Coercion in JavaScript

> "JavaScript tries to be helpful by converting types — sometimes too helpful. Master when and how it happens."

---

## 1. Concept Overview

**Type coercion** is JavaScript's automatic or explicit conversion of values from one type to another. It happens in two forms:
- **Implicit coercion**: Automatic conversion during operations (e.g., `"5" + 3`)
- **Explicit coercion**: Intentional conversion using functions (e.g., `Number("5")`)

Understanding coercion is critical because:
- It affects equality comparisons (`==` vs `===`)
- It influences arithmetic and string operations
- It can lead to subtle bugs
- It's a common interview topic

### Interview Prompts

- "What's the difference between implicit and explicit type coercion?"
- "Why does `"5" + 3` return `"53"` but `"5" - 3` returns `2`?"
- "Explain the coercion rules for the `==` operator."

## 2. Explicit Coercion Methods

### 2.1 `Number()` Constructor

Converts values to numbers using the `ToNumber` abstract operation:

```javascript
Number("42");        // 42
Number("3.14");      // 3.14
Number("");          // 0
Number("  ");        // 0 (whitespace trimmed)
Number("hello");      // NaN
Number(true);         // 1
Number(false);        // 0
Number(null);         // 0
Number(undefined);    // NaN
Number([]);           // 0 (empty array)
Number([5]);          // 5 (single element)
Number([1, 2]);       // NaN (multiple elements)
Number({});           // NaN
```

### Interview Prompts

- "What does `Number("")` return and why?"
- "Why does `Number([5])` work but `Number([1, 2])` return `NaN`?"
- "How does `Number()` handle `null` vs `undefined`?"

---

### 2.2 `String()` Constructor

Converts values to strings using the `ToString` abstract operation:

```javascript
String(42);          // "42"
String(true);        // "true"
String(false);       // "false"
String(null);        // "null"
String(undefined);   // "undefined"
String([]);          // ""
String([1, 2, 3]);   // "1,2,3"
String({});          // "[object Object]"
String({a: 1});      // "[object Object]"
```

### Interview Prompts

- "How does `String()` convert arrays and objects?"
- "Why does `String({})` return `"[object Object]"`?"
- "What's the difference between `String(null)` and `String(undefined)`?"

---

### 2.3 `Boolean()` Constructor

Converts values to booleans (truthiness-based):

```javascript
Boolean(0);          // false
Boolean(1);          // true
Boolean("");         // false
Boolean("hello");     // true
Boolean(null);        // false
Boolean(undefined);   // false
Boolean([]);          // true
Boolean({});          // true
Boolean(NaN);         // false
```

### Interview Prompts

- "How does `Boolean()` relate to truthiness?"
- "Why does `Boolean([])` return `true`?"
- "What's the difference between `Boolean()` and `!!`?"

---

### 2.4 Unary `+` Operator

Forces numeric conversion (shorthand for `Number()`):

```javascript
+"42";               // 42
+"3.14";             // 3.14
+true;               // 1
+false;              // 0
+null;               // 0
+undefined;          // NaN
+[];                 // 0
+[5];                // 5
+{};                 // NaN
```

### Interview Prompts

- "What's the difference between `+value` and `Number(value)`?"
- "Why is unary `+` sometimes preferred over `Number()`?"
- "How does unary `+` handle arrays?"

## 3. Implicit Coercion Rules

### 3.1 String Concatenation (`+`)

When one operand is a string, both are coerced to strings:

```javascript
"5" + 3;             // "53" (number coerced to string)
3 + "5";             // "35"
"hello" + true;       // "hellotrue"
null + "world";       // "nullworld"
[] + {};              // "[object Object]"
[1, 2] + [3, 4];      // "1,23,4"
```

### Interview Prompts

- "Why does `"5" + 3` return a string but `"5" - 3` returns a number?"
- "What happens when you add an array to a string?"
- "Explain the coercion in `[] + {}`."

---

### 3.2 Numeric Operations (`-`, `*`, `/`, `%`)

These operators coerce both operands to numbers:

```javascript
"5" - 3;             // 2 (both coerced to numbers)
"5" * "2";           // 10
"10" / "2";          // 5
"10" % "3";          // 1
"hello" - 1;         // NaN
true - false;        // 1
null - 1;            // -1
undefined - 1;       // NaN
```

### Interview Prompts

- "Why do subtraction and multiplication coerce to numbers?"
- "What's the result of `"5" - "3"` and why?"
- "How does `undefined` behave in numeric operations?"

---

### 3.3 Comparison Operators

#### Loose Equality (`==`)

Complex coercion rules:

```javascript
// Same type: no coercion
5 == 5;              // true
"5" == "5";          // true

// Number and String: string → number
5 == "5";            // true (string coerced to number)

// Boolean: boolean → number
true == 1;           // true
false == 0;          // true

// null and undefined: special case
null == undefined;   // true
null == 0;           // false
undefined == 0;      // false

// Object: object → primitive (ToPrimitive)
[] == 0;             // true (array → "" → 0)
[5] == 5;            // true
{} == "[object Object]"; // true
```

### Interview Prompts

- "Explain why `[] == 0` is `true`."
- "Why does `null == undefined` but `null !== undefined`?"
- "What's the coercion order for `[5] == 5`?"

---

### 3.4 Relational Operators (`<`, `>`, `<=`, `>=`)

Coerce to primitives, then compare:

```javascript
"5" < 10;            // true (string → number)
"10" < "2";          // true (lexicographic comparison!)
"a" < "b";           // true
"2" < "10";          // false (lexicographic, not numeric)
true < 2;            // true (true → 1)
null < 1;            // true (null → 0)
```

### Interview Prompts

- "Why does `"10" < "2"` return `true`?"
- "How do relational operators handle mixed types?"
- "What's the difference between string and numeric comparison?"

## 4. ToPrimitive Algorithm

When objects are coerced, JavaScript uses the `ToPrimitive` algorithm:

1. Check for `valueOf()` method
2. Check for `toString()` method
3. Throw `TypeError` if neither exists

```javascript
let obj = {
  valueOf() { return 42; },
  toString() { return "hello"; }
};

Number(obj);         // 42 (valueOf used)
String(obj);         // "hello" (toString used)
obj + "";            // "42" (valueOf, then toString for string context)
+obj;                // 42 (valueOf for number context)
```

### Interview Prompts

- "Explain the `ToPrimitive` algorithm."
- "When does `valueOf()` vs `toString()` get called?"
- "How can you customize coercion behavior for objects?"

## 5. Common Coercion Patterns

### 5.1 Converting to Number

```javascript
// Explicit
Number("42");
parseInt("42", 10);
parseFloat("3.14");
+"42";

// Implicit (in numeric context)
"42" - 0;
"42" * 1;
"42" / 1;
```

### 5.2 Converting to String

```javascript
// Explicit
String(42);
(42).toString();
42 + "";

// Implicit (in string context)
42 + "";
[1, 2, 3] + "";
```

### 5.3 Converting to Boolean

```javascript
// Explicit
Boolean(value);
!!value;

// Implicit (in boolean context)
if (value) { /* ... */ }
value && doSomething();
```

### Interview Prompts

- "What's the difference between `Number()` and `parseInt()`?"
- "When would you use `+value` vs `Number(value)`?"
- "Why is `!!value` a common pattern for boolean conversion?"

## 6. Real-World Patterns

### 6.1 Safe Number Parsing

```javascript
// ❌ Problematic
let count = Number(userInput);  // NaN if invalid

// ✅ Better
function safeNumber(value, defaultValue = 0) {
  const num = Number(value);
  return isNaN(num) ? defaultValue : num;
}

// Or use parseInt/parseFloat for strings
let count = parseInt(userInput, 10) || 0;
```

### 6.2 String Interpolation

```javascript
// Template literals (preferred)
let message = `Count: ${count}`;

// Coercion-based (works but less clear)
let message = "Count: " + count;
```

### 6.3 Default Values

```javascript
// Using || (coercion-based)
let name = user.name || "Anonymous";  // Problem: "" becomes "Anonymous"

// Using ?? (no coercion)
let name = user.name ?? "Anonymous";  // Only null/undefined
```

### Interview Prompts

- "How do you safely parse user input as numbers?"
- "When should you use template literals vs string concatenation?"
- "What's the difference between `||` and `??` for defaults?"

## 8. Common Pitfalls & Best Practices

### Pitfall 1: String Concatenation vs Addition

```javascript
// ❌ Problematic
let total = price1 + price2;  // If prices are strings, concatenates!

// ✅ Correct
let total = Number(price1) + Number(price2);
// Or ensure they're numbers
let total = +price1 + +price2;
```

### Pitfall 2: Loose Equality Confusion

```javascript
// ❌ Problematic
if (value == null) {  // Checks both null and undefined (sometimes desired)
  // But also: [] == null is false, which might be unexpected
}

// ✅ Better: Be explicit
if (value === null || value === undefined) {
  // Or use nullish coalescing
}
```

### Pitfall 3: Array/String Coercion

```javascript
// ❌ Problematic
let items = [1, 2, 3];
let display = "Items: " + items;  // "Items: 1,2,3" (might be desired)

// ✅ Better: Explicit formatting
let display = `Items: ${items.join(", ")}`;
```

### Best Practice: Use Strict Equality

```javascript
// Always prefer === unless you explicitly need coercion
value === 42
status === "active"

// Only use == when you need the coercion behavior
value == null  // Checks both null and undefined
```
