# Number Quirks in JavaScript

> "Numbers in JavaScript are deceptively simple — until they're not. Master the edge cases."

---

## 1. Concept Overview

JavaScript uses **IEEE 754 double-precision floating-point** for numbers. This means:
- All numbers are 64-bit floating-point (no separate integer type)
- Precision is limited (~15-17 significant digits)
- Special values: `NaN`, `Infinity`, `-Infinity`
- Signed zeros: `+0` and `-0`

Understanding number quirks is essential because:
- They cause real bugs in calculations
- They affect equality comparisons
- They're common interview topics
- They impact financial and scientific calculations

## 2. Floating-Point Precision

### 2.1 The 0.1 + 0.2 Problem

```javascript
0.1 + 0.2;  // 0.30000000000000004
0.1 + 0.2 === 0.3;  // false!

// Why? Binary representation
// 0.1 in binary is a repeating fraction
// 0.0001100110011001100110011001100110011001100110011001101...
```

### 2.2 Precision Limits

```javascript
// Safe integer range
Number.MAX_SAFE_INTEGER;  // 9007199254740991
Number.MIN_SAFE_INTEGER;  // -9007199254740991

// Beyond safe integers
9007199254740991 + 1;  // 9007199254740992 (correct)
9007199254740992 + 1;  // 9007199254740992 (incorrect! precision loss)
9007199254740993 === 9007199254740992;  // true (precision loss)
```

## 3. Special Number Values

### 3.1 NaN (Not a Number)

```javascript
// NaN is the result of invalid numeric operations
0 / 0;              // NaN
Math.sqrt(-1);      // NaN
Number("hello");     // NaN
parseInt("abc");     // NaN

// NaN properties
typeof NaN;         // "number" (it's a number type!)
NaN === NaN;        // false (NaN is never equal to itself)
Object.is(NaN, NaN); // true

// Checking for NaN
isNaN(NaN);         // true
isNaN("hello");      // true (coerces to NaN)
Number.isNaN(NaN);  // true (doesn't coerce)
Number.isNaN("hello"); // false (doesn't coerce)
```

### 3.2 Infinity

```javascript
// Positive infinity
Infinity;
Number.POSITIVE_INFINITY;
1 / 0;              // Infinity
Math.pow(10, 1000); // Infinity

// Negative infinity
-Infinity;
Number.NEGATIVE_INFINITY;
-1 / 0;             // -Infinity

// Properties
Infinity === Infinity;  // true
-Infinity === -Infinity; // true
Infinity > 1000000;     // true
-Infinity < -1000000;   // true

// Operations with Infinity
Infinity + 1;        // Infinity
Infinity * 2;        // Infinity
Infinity / Infinity; // NaN
1 / Infinity;       // 0
```

### 3.3 Signed Zeros

```javascript
// Positive zero
```

## 4. Number Constants

### 4.1 Maximum and Minimum Values

```javascript
Number.MAX_VALUE;           // 1.7976931348623157e+308
Number.MIN_VALUE;           // 5e-324 (smallest positive number)
Number.MAX_SAFE_INTEGER;    // 9007199254740991
Number.MIN_SAFE_INTEGER;    // -9007199254740991
Number.EPSILON;             // 2.220446049250313e-16 (smallest difference)
```

### 4.2 Using Epsilon for Comparisons

```javascript
// Comparing floating-point numbers
function areEqual(a, b) {
  return Math.abs(a - b) < Number.EPSILON;
}

areEqual(0.1 + 0.2, 0.3);  // true

// Or with custom tolerance
function areEqualTolerance(a, b, tolerance = 1e-10) {
  return Math.abs(a - b) < tolerance;
}
```

## 5. Number Methods

### 5.1 toFixed()

```javascript
let num = 3.14159;

num.toFixed(2);     // "3.14" (returns string!)
num.toFixed(0);     // "3"
num.toFixed(5);     // "3.14159"

// Rounding behavior
(2.675).toFixed(2);  // "2.67" (banker's rounding)
(2.665).toFixed(2);  // "2.67"
(2.675).toFixed(2);  // "2.67"

// Edge cases
(0.1 + 0.2).toFixed(1);  // "0.3"
Number((0.1 + 0.2).toFixed(1));  // 0.3
```

- "Why does `toFixed()` return a string?"

### 5.2 toPrecision()

```javascript
let num = 123.456;

num.toPrecision(5);  // "123.46" (5 significant digits)
num.toPrecision(3);  // "123"
num.toPrecision(7);  // "123.4560"

// Scientific notation for large numbers
(123456).toPrecision(3);  // "1.23e+5"
```

### 5.3 parseInt() and parseFloat()

```javascript
parseInt("42");        // 42
parseInt("42px");      // 42 (stops at first non-digit)
parseInt("0x10");      // 16 (hexadecimal)
parseInt("010");       // 10 (or 8 in strict mode)
parseInt("hello");     // NaN

parseFloat("3.14");    // 3.14
parseFloat("3.14abc"); // 3.14
parseFloat("0.1");     // 0.1
```

## 6. Real-World Patterns

### 6.1 Currency Calculations

```javascript
// ❌ Problematic
let price = 19.99;
let tax = price * 0.08;
let total = price + tax;  // 21.5892 (precision issues)

// ✅ Better: Use integers (cents)
let priceCents = 1999;
let taxCents = Math.round(priceCents * 0.08);
let totalCents = priceCents + taxCents;
let total = totalCents / 100;  // 21.59

// ✅ Or: Round to 2 decimal places
let total = Math.round((price + tax) * 100) / 100;
```

### 6.2 Safe Number Validation

```javascript
function isSafeNumber(value) {
  return (
    typeof value === 'number' &&
    !Number.isNaN(value) &&
    isFinite(value) &&
    value >= Number.MIN_SAFE_INTEGER &&
    value <= Number.MAX_SAFE_INTEGER
  );
}
```

### 6.3 Formatting Numbers

```javascript
// Locale-aware formatting
(1234567.89).toLocaleString('en-US');  // "1,234,567.89"
(1234567.89).toLocaleString('de-DE');  // "1.234.567,89"

// Currency formatting
(1234.56).toLocaleString('en-US', {
  style: 'currency',
  currency: 'USD'
});  // "$1,234.56"
```

## 8. Common Pitfalls & Best Practices

### Pitfall 1: Direct Floating-Point Comparison

```javascript
// ❌ Problematic
if (price === 19.99) {  // Might fail due to precision
  // ...
}

// ✅ Better
if (Math.abs(price - 19.99) < Number.EPSILON) {
  // ...
}
```

### Pitfall 2: Assuming Integer Math

```javascript
// ❌ Problematic
let result = 0.1 + 0.2;
if (result === 0.3) {  // false!
  // ...
}

// ✅ Better
let result = Math.round((0.1 + 0.2) * 100) / 100;
if (result === 0.3) {  // true
  // ...
}
```

### Pitfall 3: NaN Checking

```javascript
// ❌ Problematic
if (value === NaN) {  // Always false!
  // ...
}

// ✅ Correct
if (Number.isNaN(value)) {
  // ...
}
```

### Best Practice: Use Appropriate Precision

```javascript
// For currency: use integers (cents) or round to 2 decimals
let price = Math.round(amount * 100) / 100;

// For scientific: use appropriate tolerance
let isEqual = Math.abs(a - b) < 1e-10;

// For display: use toFixed() or toLocaleString()
let display = value.toFixed(2);
```
