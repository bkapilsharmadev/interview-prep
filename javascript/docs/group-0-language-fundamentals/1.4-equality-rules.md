# Equality Rules in JavaScript

> "Three ways to compare values — each with different rules and use cases."

---

## 1. Concept Overview

JavaScript provides three equality comparison operators:
- **`===`** (strict equality): No type coercion, compares type and value
- **`==`** (loose equality): Performs type coercion before comparison
- **`Object.is()`**: Like `===` but with special handling for `NaN` and signed zeros

Understanding these is crucial because:
- They behave differently with edge cases
- They affect code correctness and performance
- They're a common interview topic
- Choosing the wrong one can introduce bugs

### Interview Prompts

- "What's the difference between `==` and `===`?"
- "When should you use `Object.is()` instead of `===`?"
- "Why does `NaN === NaN` return `false`?"

## 2. Strict Equality (`===`)

**No type coercion** — both type and value must match exactly.

### 2.1 Primitive Comparison

```javascript
5 === 5;              // true
5 === "5";            // false (different types)
"hello" === "hello";   // true
true === true;         // true
null === null;         // true
undefined === undefined; // true
```

### 2.2 Special Cases

```javascript
NaN === NaN;           // false (NaN is never equal to itself)
+0 === -0;            // true (signed zeros are equal)
Infinity === Infinity; // true
-Infinity === -Infinity; // true
```

### 2.3 Object Comparison

```javascript
{} === {};             // false (different object references)
let obj = {};
let same = obj;
obj === same;          // true (same reference)

[] === [];             // false
let arr = [];
let sameArr = arr;
arr === sameArr;       // true
```

- "Why does `{} === {}` return `false`?"
- "How does `===` compare object references?"
- "Why is `NaN === NaN` false?"

## 3. Loose Equality (`==`)

**Performs type coercion** before comparison using the `ToNumber` algorithm.

### 3.1 Coercion Rules

1. If types are the same, use `===`
2. If one is `null` and the other is `undefined`, return `true`
3. If one is a number and the other is a string, convert string to number
4. If one is boolean, convert to number
5. If one is object, convert to primitive using `ToPrimitive`
6. Otherwise, return `false`

### 3.2 Examples

```javascript
// Same type: behaves like ===
5 == 5;               // true
"5" == "5";           // true

// Number and String
5 == "5";             // true (string → number)
"5" == 5;             // true

// Boolean
true == 1;            // true (true → 1)
false == 0;           // true (false → 0)
true == "1";          // true (true → 1, "1" → 1)

// null and undefined
null == undefined;    // true (special case)
null == 0;            // false (null doesn't coerce to 0)
undefined == 0;        // false

// Objects
[] == 0;              // true ([] → "" → 0)
[5] == 5;             // true ([5] → "5" → 5)
{} == "[object Object]"; // true
```

## 4. Object.is()

Like `===` but with special handling for edge cases:

```javascript
Object.is(5, 5);              // true
Object.is(5, "5");            // false (like ===)
Object.is(NaN, NaN);          // true (unlike ===)
Object.is(+0, -0);            // false (unlike ===)
Object.is({}, {});            // false (like ===, compares references)
```

### When to Use Object.is()

```javascript
// Checking for NaN (most common use case)
function isNaN(value) {
  return Object.is(value, NaN);
}

// Distinguishing +0 and -0
Object.is(0, -0);  // false
0 === -0;          // true

// General equality (when you want NaN and -0 handling)
if (Object.is(a, b)) {
  // Handles NaN === NaN and +0 !== -0
}
```

## 6. Real-World Patterns

### 6.1 Null/Undefined Checks

```javascript
// Using == (coercion-based)
if (value == null) {  // Checks both null and undefined
  // Handle missing value
}

// Using === (explicit)
if (value === null || value === undefined) {
  // Handle missing value
}

// Using nullish coalescing (modern)
const result = value ?? defaultValue;
```

### 6.2 NaN Detection

```javascript
// ❌ Problematic
if (value === NaN) {  // Always false!
  // Never executes
}

// ✅ Correct
if (isNaN(value)) {  // Built-in function
  // Handle NaN
}

// ✅ Better (doesn't coerce)
if (Number.isNaN(value)) {
  // Handle NaN
}

// ✅ Alternative
if (Object.is(value, NaN)) {
  // Handle NaN
}
```

### 6.3 Object Reference Checks

```javascript
// Checking if same object reference
let original = { id: 1 };
let copy = { ...original };

original === copy;  // false (different references)
Object.is(original, copy);  // false

// Shallow equality check
function shallowEqual(a, b) {
  if (a === b) return true;
  if (a == null || b == null) return false;
  if (typeof a !== 'object' || typeof b !== 'object') return false;
  
  const keysA = Object.keys(a);
  const keysB = Object.keys(b);
  
  if (keysA.length !== keysB.length) return false;
  
  for (let key of keysA) {
    if (a[key] !== b[key]) return false;
  }
  
  return true;
}
```

## 8. Common Pitfalls & Best Practices

### Pitfall 1: Using `==` Unintentionally

```javascript
// ❌ Problematic
if (count == "0") {  // Might be true when you expect false
  // ...
}

// ✅ Better
if (count === 0 || count === "0") {  // Explicit
  // ...
}
```

### Pitfall 2: NaN Comparison

```javascript
// ❌ Problematic
if (result === NaN) {  // Always false!
  // Never executes
}

// ✅ Correct
if (Number.isNaN(result)) {
  // Handle NaN
}
```

### Pitfall 3: Object Comparison

```javascript
// ❌ Problematic
if (config === defaultConfig) {  // Always false for object literals
  // Never executes
}

// ✅ Better
if (JSON.stringify(config) === JSON.stringify(defaultConfig)) {
  // Deep comparison (with limitations)
}
```

### Best Practice: Default to Strict Equality

```javascript
// Always prefer === unless you have a specific reason
value === 42
status === "active"
count === 0

// Only use == when you explicitly need coercion
value == null  // Checks both null and undefined

// Use Object.is() for edge cases
Object.is(value, NaN)
Object.is(value, -0)
```

## 9. Performance Considerations

```javascript
// === is generally faster (no coercion)
5 === 5;  // Fast

// == requires coercion checks
5 == "5";  // Slightly slower (type check + coercion)

// Object.is() has minimal overhead
Object.is(5, 5);  // Similar to ===
```
