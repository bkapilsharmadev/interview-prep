# Primitive Taxonomy in JavaScript

> "Know your data types — every primitive has a purpose and a personality."

---

## 1. Concept Overview

JavaScript has **7 primitive types**: `string`, `number`, `bigint`, `boolean`, `undefined`, `symbol`, and `null`. Each primitive is immutable, stored by value, and has distinct characteristics that affect how you work with them in code.

Understanding primitives is foundational because:
- They determine memory behavior (value semantics)
- They affect equality comparisons
- They influence type coercion rules
- They impact performance characteristics

## 2. What Exactly Is a Primitive? (Spec-Level Summary)

Primitives are immutable, atomic values defined in ECMAScript §6.1. They have:

- **No identity** — Two primitives with the same value are indistinguishable
- **No prototypes** — Cannot have methods attached directly
- **No extensible properties** — Cannot add properties
- **No internal object slots** (exceptions noted below)

### Temporary Wrapper Objects

When you call a method on a primitive, like:

```javascript
"hi".toUpperCase();
```

JavaScript creates a temporary wrapper object (like `new String("hi")`), invokes the method, then immediately discards the wrapper. The primitive itself remains untouched.

## 3. The Seven Primitives

### 3.1 `undefined` — System-Level Absence

`undefined` represents "no value assigned." Only the JavaScript engine produces `undefined` automatically.

**When does `undefined` appear?**

```javascript
// Declared but unassigned variables
let x;
console.log(x); // undefined

// Missing object properties
let obj = {};
console.log(obj.missing); // undefined

// Missing function arguments
function test(a) {
  console.log(a); // undefined if not provided
}
test();

// Functions without return statements
function noReturn() {
  // No return
}
console.log(noReturn()); // undefined
```

**Why `undefined` exists separately from `null`?**

Because JavaScript distinguishes between:
- **Not assigned** → `undefined`
- **Intentionally empty** → `null`

This allows APIs to differentiate between "value missing" and "value deliberately cleared."

### 3.2 `null` — Intentional Absence

`null` represents an explicit, intentional "no value." It often indicates something is expected later.

```javascript
let user = null; // intentionally empty, will be assigned later
```

**Why `typeof null === "object"`?**

This comes from a 1995 pointer-tagging system:
- JavaScript tagged objects with a bit pattern ending in `000`
- The `null` value was internally represented as all zero bits, which also ends in `000`

**Result:**

```javascript
typeof null === "object"; // historical bug
```

It cannot be fixed now due to web compatibility.

### 3.3 `boolean` — Logical True/False

The Boolean type has only two values: `true` and `false`.

**JavaScript truthiness rules can surprise developers:**

```javascript
Boolean("");     // false
Boolean("0");    // true (non-empty string)
Boolean([]);     // true (empty array is truthy!)
Boolean({});     // true (empty object is truthy!)
Boolean(0);      // false
Boolean(null);  // false
Boolean(undefined); // false
```

**Avoid Boolean wrapper objects:**

```javascript
new Boolean(false); // truthy object!
if (new Boolean(false)) {
  console.log("This runs!"); // Because it's an object
}
```

### 3.4 `number` — IEEE-754 Double Precision

JavaScript's Number type is a 64-bit floating point value. It represents:
- Integers (limited to ±2^53 - 1 for safe integers)
- Fractions
- `NaN`
- `Infinity`
- `-Infinity`
- `-0` (negative zero)

**Precision Pitfall:**

```javascript
0.1 + 0.2 !== 0.3  // true!
// Result: 0.30000000000000004
```

Floating-point rounding causes this.

**Special behaviors:**

```javascript
NaN === NaN        // false
Object.is(NaN, NaN) // true
0 === -0           // true
Object.is(0, -0)    // false
```

Numbers remain ideal for timestamps, counters, basic arithmetic, and most everyday calculations.

### 3.5 `bigint` — Arbitrary Precision Integers

BigInt was added in ES2020 to handle integers beyond Number's safe range.

```javascript
const id = 9007199254740993n;
const huge = BigInt("999999999999999999999");
```

**Key rules:**

```javascript
// You cannot mix BigInt and Number:
10n + 5  // TypeError: Cannot mix BigInt and number

// Explicit conversion required:
10n + BigInt(5)  // 15n
Number(10n) + 5  // 15
```

**Ideal for:**
- Cryptography
- High-precision math
- Large sequences/IDs
- Financial applications

BigInt is slower than Number but guarantees exact precision.

### 3.6 `string` — Immutable UTF-16 Sequences

Strings in JavaScript are immutable, meaning they cannot be changed after creation.

```javascript
let s = "hello";
s[0] = "H"; // ignored, no mutation
console.log(s); // "hello" (unchanged)

// Concatenation creates new strings
let newStr = s + " world"; // Creates new string
console.log(s); // "hello" (still unchanged)
```

**Why are strings index-accessible like arrays?**

Because JavaScript temporarily wraps them in a String object:

```javascript
"hello"[1]; // "e" (works via temporary wrapper)
```

Indexing works because the wrapper allows reading, but since primitive strings are immutable, "writing" does nothing.

**UTF-16 and surrogate pairs:**

Some characters take two code units:

```javascript
"💙".length // 2 (not 1!)
"hello".length // 5
```

This is why `length` does not always equal number of visible characters.

### 3.7 `symbol` — Unique, Immutable Identity Values

A Symbol is a unique primitive value commonly used for "private" properties or internal object keys.

```javascript
const role = Symbol("role");
const user = { [role]: "admin" };

console.log(user[role]); // "admin"
console.log(user.role);  // undefined (not accessible via string)
```

**Why symbols exist:**

Symbols solve problems involving:
- Hidden properties
- Avoiding key collisions
- Creating internal-only object fields
- Implementing protocols via well-known symbols

**Local Symbols:**

Each call creates a new, unique value:

```javascript
Symbol("id") === Symbol("id"); // false
```

**Global Symbol Registry:**

Reuses the same symbol:

```javascript
Symbol.for("id") === Symbol.for("id"); // true
```

**Symbol cannot be auto-converted to string:**

```javascript
"hello" + Symbol() // TypeError: Cannot convert a Symbol value to a string
```

This prevents accidental leakage of Symbol-based internal keys.

## 4. Internal Slots: Why Only Some Primitives Have Them

Primitives do not have extensible internal slots like objects, but they may have intrinsic data slots:

| Primitive | Slot | Purpose |
|-----------|------|---------|
| String | `[[StringData]]` | UTF-16 sequence |
| Symbol | `[[Description]]` | Optional description |
| BigInt | `[[BigIntData]]` | Arbitrary-length number |

These are not object fields. They simply represent the underlying data required for the primitive to exist.

## 5. Why JSON Does Not Support `undefined`

JSON is defined by ECMA-404 and RFC 8259. Its allowed values are:
- object
- array
- string
- number
- boolean
- `null`

There is no `undefined` in the grammar.

**Reasons:**

1. **`undefined` is JS-specific** — Most languages do not have an equivalent value.
2. **JSON is a data format, not a language runtime** — `undefined` arises in runtime behavior only (e.g., missing variables).
3. **JSON enforces a single "empty" value → `null`** — To avoid duplication of meaning.

**What happens in practice?**

```javascript
JSON.stringify({ a: undefined }); // "{}" (key disappears)
JSON.stringify([undefined]);      // "[null]" (becomes null)
JSON.stringify({ a: null });      // '{"a":null}' (null is preserved)
```

Object keys with `undefined` disappear. Array elements with `undefined` become `null`.

## 7. Type Detection Patterns

### 7.1 Using `typeof`

```javascript
typeof "hello"      // "string"
typeof 42           // "number"
typeof 42n          // "bigint"
typeof true         // "boolean"
typeof undefined    // "undefined"
typeof Symbol()     // "symbol"
typeof null         // "object" (quirk!)
typeof {}           // "object"
typeof []           // "object"
typeof function(){} // "function"
```

### 7.2 Reliable Primitive Checks

```javascript
function isPrimitive(value) {
  return (
    value === null ||
    (typeof value !== 'object' && typeof value !== 'function')
  );
}

// Or more explicit
function isPrimitiveStrict(value) {
  const type = typeof value;
  return (
    type === 'string' ||
    type === 'number' ||
    type === 'bigint' ||
    type === 'boolean' ||
    type === 'undefined' ||
    type === 'symbol' ||
    value === null
  );
}
```

## 8. Real-World Patterns

### 8.1 Default Value Assignment

```javascript
// Using nullish coalescing for primitives
let name = user.name ?? "Anonymous";
let count = items.length ?? 0;

// vs undefined check
let value = obj.prop !== undefined ? obj.prop : defaultValue;
```

### 8.2 Type-Safe Comparisons

```javascript
// Always use === for primitives (except when you need coercion)
if (status === "active") { /* ... */ }
if (count === 0) { /* ... */ }
if (value === null) { /* ... */ }

// For optional values
if (value == null) {  // Checks both null and undefined
  // Handle missing value
}
```

### 8.3 Primitive Wrappers (Avoid!)

```javascript
// Don't use primitive constructors
let str = new String("hello");  // Creates object, not primitive!
console.log(typeof str);  // "object"

// Use literals instead
let str2 = "hello";
console.log(typeof str2);  // "string"
```

## 10. Common Pitfalls & Best Practices

### Pitfall 1: Confusing `null` and `undefined`

```javascript
// Bad: Treating them the same without understanding
if (value == null) { /* handles both */ }

// Better: Be explicit about intent
if (value === null) { /* explicitly null */ }
if (value === undefined) { /* missing value */ }
```

### Pitfall 2: Mutating Strings

```javascript
// Strings are immutable — operations return new strings
let str = "hello";
str.toUpperCase();  // Doesn't modify str!
let upper = str.toUpperCase();  // Correct
```

### Pitfall 3: Number Precision

```javascript
// Floating-point arithmetic isn't exact
0.1 + 0.2 === 0.3  // false!

// Solutions:
Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON  // true
// Or use integers (cents instead of dollars)
```

### Pitfall 4: Using Primitive Wrappers

```javascript
// ❌ Problematic
let bool = new Boolean(false);
if (bool) {  // true! (it's an object)
  console.log("This runs");
}

// ✅ Correct
let bool = false;
if (bool) {  // false
  // Doesn't run
}
```

### Best Practice: Use Strict Equality

```javascript
// Always prefer === for primitives
value === 42
status === "active"
count === 0

// Only use == when you explicitly need coercion
value == null  // Checks both null and undefined
```
