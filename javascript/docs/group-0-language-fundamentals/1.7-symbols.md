# Symbols in JavaScript

> "Unique, immutable identifiers that solve property collision problems."

---

## 1. Concept Overview

**Symbols** (ES2015) are unique, immutable primitive values used primarily as object property keys. Every `Symbol()` call creates a new, unique value, making them perfect for:
- Avoiding property name collisions
- Creating private-like properties
- Implementing well-known protocols (iteration, toString, etc.)
- Adding metadata to objects

Key characteristics:
- Every Symbol is unique (even with same description)
- Symbols are not enumerable in `for...in` loops
- Symbols are not included in `Object.keys()` or `Object.getOwnPropertyNames()`
- Symbols can be retrieved with `Object.getOwnPropertySymbols()`

## 2. Creating Symbols

### 2.1 Basic Creation

```javascript
// Every call creates a new Symbol
let sym1 = Symbol();
let sym2 = Symbol();
console.log(sym1 === sym2);  // false

// With description (for debugging)
let sym3 = Symbol("description");
let sym4 = Symbol("description");
console.log(sym3 === sym4);  // false (still unique!)
```

### 2.2 Symbol.for() - Global Registry

```javascript
// Symbol.for() creates or retrieves from global registry
let sym1 = Symbol.for("key");
let sym2 = Symbol.for("key");
console.log(sym1 === sym2);  // true (same symbol from registry)

// Symbol.keyFor() gets the key for a registered symbol
let key = Symbol.keyFor(sym1);  // "key"
```

## 3. Using Symbols as Property Keys

### 3.1 Object Properties

```javascript
let id = Symbol("id");
let user = {
  name: "John",
  [id]: 123  // Computed property name
};

console.log(user[id]);  // 123
console.log(user.name);  // "John"

// Symbols are not enumerable
for (let key in user) {
  console.log(key);  // Only "name"
}

console.log(Object.keys(user));  // ["name"]
console.log(Object.getOwnPropertySymbols(user));  // [Symbol(id)]
```

### 3.2 Private-Like Properties

```javascript
// Symbols can create "private" properties (not truly private, but hidden)
let _private = Symbol("private");

class MyClass {
  constructor(value) {
    this[_private] = value;
  }
  
  getPrivate() {
    return this[_private];
  }
}

let obj = new MyClass("secret");
console.log(obj._private);  // undefined
console.log(obj.getPrivate());  // "secret"
```

## 4. Well-Known Symbols

JavaScript provides built-in Symbols that control language behavior:

### 4.1 Symbol.iterator

```javascript
// Makes objects iterable
let collection = {
  items: [1, 2, 3],
  [Symbol.iterator]() {
    let index = 0;
    return {
      next: () => {
        if (index < this.items.length) {
          return { value: this.items[index++], done: false };
        }
        return { done: true };
      }
    };
  }
};

for (let item of collection) {
  console.log(item);  // 1, 2, 3
}
```

### 4.2 Symbol.toStringTag

```javascript
class MyClass {
  get [Symbol.toStringTag]() {
    return "MyClass";
  }
}

let obj = new MyClass();
console.log(obj.toString());  // "[object MyClass]"
console.log(Object.prototype.toString.call(obj));  // "[object MyClass]"
```

### 4.3 Symbol.toPrimitive

```javascript
let obj = {
  value: 42,
  [Symbol.toPrimitive](hint) {
    if (hint === "number") return this.value;
    if (hint === "string") return String(this.value);
    return this.value;  // default
  }
};

console.log(+obj);  // 42
console.log(String(obj));  // "42"
console.log(obj + 1);  // 43
```

## 6. Real-World Patterns

### 6.1 Avoiding Property Collisions

```javascript
// Library code
let LIBRARY_KEY = Symbol("library");

function addLibraryData(obj, data) {
  obj[LIBRARY_KEY] = data;
}

// User code (won't conflict)
let userObj = { name: "John" };
addLibraryData(userObj, { version: "1.0" });

// User can't accidentally access or overwrite
console.log(userObj[LIBRARY_KEY]);  // undefined (unless they have the Symbol)
```

### 6.2 Metadata

```javascript
let METADATA = Symbol("metadata");

function addMetadata(obj, metadata) {
  obj[METADATA] = metadata;
}

function getMetadata(obj) {
  return obj[METADATA];
}
```

### 6.3 Custom Iteration

```javascript
class Range {
  constructor(start, end) {
    this.start = start;
    this.end = end;
  }
  
  [Symbol.iterator]() {
    let current = this.start;
    let end = this.end;
    return {
      next() {
        if (current <= end) {
          return { value: current++, done: false };
        }
        return { done: true };
      }
    };
  }
}

for (let num of new Range(1, 5)) {
  console.log(num);  // 1, 2, 3, 4, 5
}
```

## 8. Common Pitfalls & Best Practices

### Pitfall 1: Assuming Symbols Are Truly Private

```javascript
// ❌ Symbols are not truly private
let _secret = Symbol("secret");
let obj = { [_secret]: "value" };

// Can still access if you have the Symbol
console.log(obj[_secret]);  // "value"

// ✅ Better: Use WeakMap for true privacy
let _secrets = new WeakMap();
_secrets.set(obj, "value");
```

### Pitfall 2: Forgetting Symbol Enumeration

```javascript
// ❌ Symbols won't show up in normal iteration
let obj = {
  name: "John",
  [Symbol("id")]: 123
};

for (let key in obj) {
  console.log(key);  // Only "name"
}

// ✅ Use Object.getOwnPropertySymbols()
let symbols = Object.getOwnPropertySymbols(obj);
```

### Pitfall 3: JSON Serialization

```javascript
// ❌ Symbols are ignored in JSON
let obj = {
  name: "John",
  [Symbol("id")]: 123
};

JSON.stringify(obj);  // '{"name":"John"}' (Symbol ignored)

// ✅ Convert to regular property if needed for JSON
let obj2 = {
  name: "John",
  id: 123  // Regular property for JSON
};
```

### Best Practice: Use When Appropriate

```javascript
// Use Symbols when:
// 1. Need unique property keys
// 2. Want to avoid name collisions
// 3. Implementing well-known protocols
// 4. Adding metadata that shouldn't be enumerable

// Don't use Symbols when:
// 1. Need JSON serialization
// 2. Need enumerable properties
// 3. Simple string keys work fine
```
